## Valheim 服务端到底吃什么资源

它不是那种「核心越多越好」的服务端。世界模拟基本跑在单线程上，所以一颗主频高的核心，比多出来的四个核心更有用。这也是为什么很多开服教程推荐游戏云机型——那些机器的卖点就是单核频率。

内存则是另一回事，它主要跟**世界的复杂程度**走，而不是跟在线人数走。服务端会把「有玩家活动的区域」整个加载进内存：十个人挤在同一片基地里只算一个区域，十个人各自跑向不同生物群系就得同时加载十个。社区和一些主机商实测出来的数字大致是这样：

| 场景 | 内存占用 |
| --- | --- |
| 全新的 1.0 世界，无人上线 | 约 1.3 GB |
| 最多 10 人同一片基地活动 | 2-3 GB |
| 10 人分散在 10 个不同区域 | 最多约 5.5 GB |
| 连续运行几天之后 | 在上面基础上再加约 1 GB |

前两行 4GB 内存就够，四行全覆盖建议 8GB。硬盘不占地方，服务端文件 2GB 出头，10-15GB 空间足够，但要给不断累积的备份留余量。

按这个思路，配置档位大致是：

| 你的情况 | 建议配置 |
| --- | --- |
| 2-5 人原版，建筑规模一般 | 2 核高主频 + 4GB，SSD，5-10M 上行 |
| 6-10 人长期世界、大型基地 | 4 核高主频 + 8GB，10M 上行起步 |
| 装模组（BepInEx 系） | 在上面一档基础上加内存，单核频率优先 |

网上有人用 2 核 4G 的机器每小时崩一次要手动重启，也有人同样的 2 核 4G 带 4 个人玩得很顺。差别通常不在机器，而在基地规模、模组数量和地图探索范围——这几个变量决定了内存里同时挂着多少区域。

## 搭建流程：Ubuntu + SteamCMD，一次跑通

系统建议 Ubuntu 22.04 或 Debian 12。以下命令都以 root 或带 sudo 的普通用户执行。

**第一步：装 SteamCMD 和依赖**

bash
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install -y steamcmd lib32gcc-s1 libatomic1 libpulse-dev libpulse0


SteamCMD 是 32 位程序，所以要先把 i386 架构打开；后面三个库是 Iron Gate 官方文档要求 Linux 服务端安装的。

**第二步：下载服务端**

bash
mkdir -p ~/valheim
steamcmd +force_install_dir ~/valheim +login anonymous +app_update 896660 validate +quit


`+force_install_dir` 必须写在 `+login` 前面才会生效。下载完成后目录里会出现 `valheim_server.x86_64` 和自带的 `start_server.sh`——后者每次更新都会被覆盖，所以别改它，另写一个。

**第三步：写启动脚本**

新建 `run.sh`，放在服务端同目录：

bash
#!/bin/bash
export LD_LIBRARY_PATH=./linux64:$LD_LIBRARY_PATH
export SteamAppId=892970

./valheim_server.x86_64 -nographics -batchmode \
  -name "英灵神殿" \
  -port 2456 \
  -world "Midgard" \
  -password "至少五位密码" \
  -public 1 \
  -savedir "$HOME/valheim/saves"


Valheim 服务端没有配置文件，所有设置都是启动参数。常用的几个：

| 参数 | 作用 |
| --- | --- |
| `-name` | 服务器名，显示在服务器列表里 |
| `-port` | 游戏端口，默认 2456，服务端会连带占用后一个端口 |
| `-world` | 世界名。存档不存在就生成新的，改这个名字等于换一个世界 |
| `-password` | 进入密码，至少 5 位，且**不能出现在服务器名或世界名里** |
| `-public 1 / 0` | 1 会出现在游戏内社区列表，0 只能靠 IP 直连 |
| `-savedir` | 存档目录，建议显式指定，方便备份 |
| `-crossplay` | 走官方中继，主机平台玩家才能进 |
| `-saveinterval` | 保存间隔秒数，默认 1800（30 分钟） |
| `-instanceid` | 一台机器跑多个服时用来区分实例 |

密码那条规则是真的会拦住你：世界名取 Midgard、密码设成 gard，服务端会直接拒绝启动。它只在日志里报错，面板上看不出来，第一次踩到容易一脸懵。

**第四步：用 systemd 托管**

官方停止服务端的方式是 Ctrl+C（也就是 SIGINT），服务端收到信号后会写完存档再退出。systemd 默认发的是 SIGTERM，所以要改掉，不然重启或关机时存档可能来不及落盘。

ini
[Unit]
Description=Valheim dedicated server
After=network-online.target

[Service]
WorkingDirectory=/root/valheim
Environment=LD_LIBRARY_PATH=/root/valheim/linux64
Environment=SteamAppId=892970
ExecStart=/root/valheim/valheim_server.x86_64 -nographics -batchmode \
  -name "英灵神殿" -port 2456 -world "Midgard" \
  -password 你的密码 -public 1 -savedir /root/valheim/saves
KillSignal=SIGINT
TimeoutStopSec=120
Restart=on-failure
RestartSec=15

[Install]
WantedBy=multi-user.target


普通账号跑服务端会更安全，把 `WorkingDirectory` 和路径换成对应用户的家目录即可。密码别直接写在 unit 文件里——那个文件系统上所有用户都能读，放进 `EnvironmentFile` 并设成 600 权限更稳妥。

bash
sudo systemctl daemon-reload
sudo systemctl enable --now valheim
journalctl -u valheim -f


日志里出现服务端已连接、世界已加载，就说明服起来了。第一次启动新世界会慢一些，因为要生成地图。

## 端口和联机方式

Valheim 只用 UDP，不开任何 TCP 端口也能正常联机——很多人排查半天连不上，就是因为路由器上开的是 TCP 规则，看起来完全正确但毫无作用。

bash
sudo ufw allow 2456:2458/udp


三个端口分别是：2456 游戏数据，2457 Steam 查询（不开的话服务器照跑，但永远不出现在列表里），2458 给 crossplay 和部分模组用。

| 联机方式 | 谁能进来 | 需要开端口 |
| --- | --- | --- |
| 直连 IP | Steam 玩家 | UDP 2456-2458 |
| 加 `-crossplay` 启动 | Steam、Xbox、微软商店、PS5、Switch 2 | 不需要，流量走官方中继 |

好友进服的两种方式：直连的在「加入游戏」里填 `你的公网IP:2456`；开了 crossplay 的服务器会生成一个 6 位连接码，把码发到群里，主机玩家输入即可。crossplay 的代价是中继多一跳、延迟略高，而且主机平台玩家装不了模组——如果你的服要打 BepInEx 模组，那基本就是 Steam 专属服，这两条路要提前选好。

## 存档、管理和不丢档

Linux 默认存档目录在 `~/.config/unity3d/IronGate/Valheim/`，Windows 在 `%USERPROFILE%\AppData\LocalLow\IronGate\Valheim`。用 `-savedir` 指定过就按你指定的位置找。

三个文本文件决定谁能做什么，一行一个 ID：

- `adminlist.txt`：能用管理员命令（踢人、封禁）的玩家
- `bannedlist.txt`：禁止进入的玩家
- `permittedlist.txt`：白名单。只要里面写了任意一个 ID，不在名单上的人一律进不来

ID 格式是 `平台_用户ID`，区分大小写。最省事的做法是让玩家先正常进一次服，然后从他的 F2 面板或者服务器日志里复制准确的那串字符——自己凭记忆拼一个出来，通常不生效。

备份方面，服务端每 30 分钟自动保存一次，还会自己保留几份滚动备份（`-backups`、`-backupshort`、`-backuplong` 控制数量和间隔）。但这些备份跟世界存在同一块盘上，能救命的是它挡住一次存档损坏，挡不住硬盘故障或者误删目录。真正靠谱的做法是定期把整个存档目录打包传到别的地方，先停服再打包能得到一致快照，凌晨四点重启一次对玩家没什么影响。

更新服务端也很简单，停服后重跑一遍安装命令：

bash
sudo systemctl stop valheim
steamcmd +force_install_dir ~/valheim +login anonymous +app_update 896660 validate +quit
sudo systemctl start valheim


## 常见问题

**提示版本不兼容。** 服务端和客户端版本对不上，跑一遍上面的更新命令。游戏每推一个补丁，双方都得跟版本，服务器不更新，玩家就进不来。

**服务器在跑，但列表里搜不到。** 检查是不是写成了 `-public 0`，或者 UDP 2457 没放行。

**人一多就卡、传送时加载很慢。** 大概率是内存不够，服务端不得不在磁盘和内存之间来回倒腾区域数据。先把基地周围的灯、刷怪点、散落物品清一清，这比换机器见效快。

**开服几小时必崩。** 先看内存曲线，再看模组。模组只在服务端装而客户端没装，或者版本对不上，常见表现就是连上之后被踢出去。

**玩家人数上限是多少？** 10 人，官方定位就是 1-10 人的游戏，启动参数里没有提高上限的选项。社区有模组能解开这个限制，但每个玩家都得装匹配的客户端，主机平台玩家直接排除在外。
